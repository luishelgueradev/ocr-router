# Quick Task 260724-64d: close Phase 3 verification gaps + monotonic clock defect

Closes the two gaps left open by `.planning/phases/03-input-pipeline/03-VERIFICATION.md`
(verdict `gaps_found`) and its Human-Verification item #1, plus a clock defect found
while re-auditing the phase after a session interruption.

## Task 1 — G-1: HEIC ispe bounds off-by-four + untyped escape

**Files:** `lib/v1/input/image-normalize.js`, `test/image-normalize.test.js`

**Problem (reproduced):** `assertHeicWithinCap` bounds-checks `i + 12 <= buf.length`
but then reads `buf.readUInt32BE(i + 12)`, which needs `i + 16` bytes. A 16-byte
upload sniffing as HEIC throws a raw `RangeError` with no `status`:

```
THROWN: RangeError | code=ERR_OUT_OF_RANGE | status=undefined  ->  500 internal_error
```

That is precisely the alerting-signal destruction WR-03 was raised to remove,
surviving on the one path the WR-03 fix did not cover, because
`assertHeicWithinCap` is called OUTSIDE the try that types decoder errors.

**Action:** Require the full 16 bytes the reads consume before reading. Move the
guard call inside the WR-03 try so no future arithmetic slip can escape untyped.

**Verify:** A 16-byte HEIC-sniffing buffer yields a typed 4xx (`status` 413/422),
not a `RangeError`. Existing HEIC tests stay green.

**Done:** No input can make the HEIC path emit an untyped error.

## Task 2 — G-2: ispe scan blind to legal box encodings + missing memory ceiling

**Files:** `lib/v1/input/image-normalize.js`, `docker-compose.yml`, `test/image-normalize.test.js`

**Problem:** The scan counts an `ispe` only when `readUInt32BE(i - 4) === 20`, so a
legal 64-bit extended box (`size == 1` + 8-byte `largesize`), which libheif accepts,
bypasses the pixel guard entirely. The module comment calls the residual "no
recognizable ispe", which is narrower than the truth, and names the container's own
memory limit as the fallback bound — but no `mem_limit` or `--max-old-space-size`
exists anywhere in the deploy stack, so that fallback does not exist.

**Action:** Accept every legal box encoding that can carry an `ispe` payload
(32-bit size, 64-bit extended size, and `size == 0` meaning "to end of file"), taking
the largest declared extent. Add a `mem_limit` to `docker-compose.yml` so the
documented fallback is real. Correct the comment to state the true residual.

**Verify:** A HEIC declaring an over-cap image through a 64-bit box is rejected 413.
`docker compose config` resolves with the memory limit present.

**Done:** The guard is not bypassable by box encoding, and its stated fallback exists.

## Task 3 — Monotonic clock for all duration/deadline arithmetic

**Files:** `lib/v1/clock.js` (new), `lib/v1/cascade/runner.js`, `lib/v1/worker.js`,
`lib/v1/input/page-pipeline.js`, `lib/v1/health.js`, `lib/v1/shutdown.js`,
`lib/providers/ocrspace.js`, `lib/providers/ollama.js`, `test/worker-input.test.js`,
`test/clock.test.js` (new)

**Problem (reproduced):** Every budget and deadline is computed from `Date.now()`,
the wall clock. Captured from a real failing run of the CASC-08 budget test:

```
DBG-FAIL stopped_reason=passed elapsed=-791
DBG-attempts=[{"engine":"ocrspace-engine2","time_ms":-791,...}]
```

The wall clock stepped ~1.1s backward mid-run, so `remaining = deadline - Date.now()`
inflated past `minSliceMs` and the runner escalated a tier the budget had already
spent. It reproduces about 1 in 3 full-suite runs under load. The same arithmetic
backs `worker.js` `deadline = Date.now() + CAPS.MAX_JOB_MS` — the single authoritative
job deadline that JOB-04 / CASC-08 exist to enforce. On a VPS running NTP, a forward
step kills jobs early and a backward step lets them run past MAX_JOB_MS. Negative
durations also leak into traces and logs.

**Action:** Add `lib/v1/clock.js` exposing `monotonicMs()` (`performance.now()`,
immune to wall-clock steps) and `wallMs()`. Migrate every elapsed/deadline
computation to `monotonicMs()`. Leave `jobs.js` `expires_at` on the wall clock — it
is a client-facing absolute timestamp and is correct as-is. Call through the module
object (not a destructured binding) so tests can substitute the clock. Update the
WR-02 test to drive the injected clock instead of monkeypatching global `Date.now`.

**Verify:** New test asserts the cascade budget still stops correctly while the wall
clock is stepped backward mid-run. Full suite green across repeated runs under load.

**Done:** No budget or deadline depends on the wall clock.
